# LiteGS 创新点开发周会制度

**制定时间**: 2026-03-27  
**目的**: 协调多团队并行开发，确保信息同步，及时解决冲突  
**频率**: 每周 3 次（周一/三/五）  
**参与人员**: 所有创新点开发团队成员  

---

## 会议安排

### 周一：进度同步会

**时间**：周一上午 10:00-11:00 (1 小时)  
**主持人**：项目负责人  
**记录员**：轮值（每周更换）

**议程**：
1. **各团队进度汇报**（30 分钟）
   - 团队 A：动态高斯更新（5 分钟）
   - 团队 B：跨帧时序复用（5 分钟）
   - 团队 C：神经高斯混合（5 分钟）
   - 其他团队（各 3 分钟）

2. **关键问题讨论**（20 分钟）
   - 技术难点
   - 资源需求
   - 风险识别

3. **本周计划确认**（10 分钟）
   - 各团队本周目标
   - 里程碑检查
   - 资源协调

**输出**：
- 会议纪要
- 本周任务清单
- 风险清单

---

### 周三：技术讨论会

**时间**：周三下午 14:00-16:00 (2 小时)  
**主持人**：技术负责人  
**记录员**：轮值

**议程**：
1. **技术专题分享**（60 分钟）
   - 每周 1-2 个技术主题
   - 深入讨论技术细节
   - 经验分享

2. **冲突解决**（30 分钟）
   - 代码冲突协调
   - 架构设计讨论
   - 接口定义确认

3. **代码审查**（30 分钟）
   - 重要 PR 审查
   - 代码规范检查
   - 最佳实践分享

**输出**：
- 技术决策记录
- 代码审查意见
- 技术分享材料

---

### 周五：集成规划会

**时间**：周五上午 10:00-11:30 (1.5 小时)  
**主持人**：集成负责人  
**记录员**：轮值

**议程**：
1. **本周成果演示**（45 分钟）
   - 各团队演示本周进展
   - 性能测试结果展示
   - 问题反馈

2. **集成计划**（30 分钟）
   - 下周集成目标
   - 集成批次规划
   - 测试计划

3. ** retrospective**（15 分钟）
   - 本周做得好的
   - 需要改进的
   - 改进行动

**输出**：
- 集成计划
- 测试结果报告
- 改进行动清单

## Git 分支同步流程

### 每日同步

**要求**：
- 每天早上 pull 最新 develop 分支
- 每天至少 commit 一次
- 每天结束前 push 到远程

**命令**：
```bash
# 早上开始工作
git checkout develop
git pull origin develop
git checkout feature/your-feature
git rebase develop

# 晚上提交代码
git add .
git commit -m "feat: 今日进展"
git push origin feature/your-feature
```

### 每周同步

**周一前**：
- 确保所有分支已 push 到远程
- 更新任务看板
- 准备进度汇报材料

**周五后**：
- 检查所有分支状态
- 清理已合并的旧分支
- 更新项目看板

## 会议规则

### 基本规则
1. **准时参会**：提前 5 分钟进入会议室
2. **充分准备**：提前准备汇报材料
3. **专注讨论**：会议期间不看手机
4. **结果导向**：每个议题都有明确结论

### 发言规则
1. **时间控制**：严格按照规定时间
2. **对事不对人**：聚焦技术和问题
3. **建设性意见**：提出问题的同时给出建议
4. **尊重他人**：不打断他人发言

### 决策规则
1. **数据驱动**：基于测试数据和事实
2. **充分讨论**：每个人都有发言机会
3. **负责人决定**：讨论后由负责人决策
4. **记录在案**：所有决策都要记录
