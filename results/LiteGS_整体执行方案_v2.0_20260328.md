## 二、整体执行方案

### 2.1 短期行动（1-2 周）

#### 行动 1: 移除/禁用 FP8 功能

**原因**：
- 性能严重下降（-1028%）
- 硬件限制严重（仅 H100/B100 支持）
- 与 LiteGS 跨平台原则相悖

**执行方案**：
```
选项 A: 直接移除
- 删除 optimizer.py 中的 FP8 相关代码
- 删除 arguments.py 中的 FP8 参数
- 删除测试脚本 fp8_mixed_precision_1000iter.py

选项 B: 标记 DEPRECATED（推荐）
- 保留代码但添加废弃警告
- 在文档中说明原因
- 等待未来硬件普及后再考虑
```

#### 行动 2: 重新测试 Enhanced Frustum Culling

**原因**：上次测试数据异常（17200s vs 18691s），需要验证

**执行方案**：
```
1. 检查测试脚本配置
2. 运行规范的 1000 次迭代测试
3. 验证数据合理性
4. 记录测试结果
```

### 2.2 中期优化（1-2 个月）

#### 优化 1: 渐进式点数 + 渐进式分辨率（DashGaussian 思想）

**核心思路**：将 Progressive Densify 与分辨率调度结合

**预期收益**：显著加速（理论可达 40%+）

**实现方案**：
```
Phase 1: 调研 DashGaussian 论文
- 分辨率调度策略
- 与点数控制的协同机制

Phase 2: 设计双渐进控制器
- ProgressiveDensifyController 扩展
- 集成渲染分辨率参数

Phase 3: 实现与测试
- 修改训练管线
- 1000/5000/30000 迭代测试
```

#### 优化 2: 重要性引导的分裂策略

**核心思路**：基于梯度/Hessian 信息选择分裂对象

**预期收益**：提升分裂效率，提高收敛速度

### 2.3 长期规划（3-6 个月）

#### 方向 1: 端到端优化

- 从数据加载到渲染的全链路优化
- 与 LiteGS 现有优化（warp rasterization, Morton code）深度结合

#### 方向 2: 自适应系统

- 根据场景复杂度自动选择最优参数
- 实现"一键最优"用户体验
