### 2.2 第二层 Why：为什么 70/30 比例会稀释收益？

**理论缺陷**:

1. **70/30 比例缺乏理论依据**
   - ε-greedy 策略中典型值为 ε=0.1 或 ε=0.01
   - 30% 的随机比例过于保守，过度削弱了利用 (exploitation)
   
2. **固定比例缺乏自适应性**
   - 训练早期需要更多探索 (高随机比例)
   - 训练后期需要更多利用 (高重要性比例)
   - 固定 70/30 无法适应训练动态

### 2.3 第三层 Why：为什么重要性分数区分度不足？

**归一化策略问题**:

```python
# L431-436: 归一化逻辑
min_score = importance_score.min()
max_score = importance_score.max()
if max_score > min_score:
    importance_score = (importance_score - min_score) / (max_score - min_score + 1e-8)
else:
    importance_score = torch.ones_like(importance_score) * 0.5  # ⚠️ 退化情况
```

**问题分析**:

1. **全局归一化导致分布趋同**
   - 当分数分布不均匀时，归一化会压缩差异
   - 特别是当大部分点分数接近时，区分度严重下降

2. **退化情况处理不当**
   - 当 `max == min` 时，所有点都得 0.5 分
   - 这在实际训练中经常发生（当梯度分布均匀时）

3. **缺乏鲁棒性**
   - 对异常值敏感
   - 未考虑分数分布的统计特性

**改进方案**:
- 使用分位数归一化 (如基于 25%/75% 分位数)
- 或使用 Z-score 标准化 + Sigmoid 映射

### 2.4 第四层 Why：为什么梯度方差作为重要性指标存在局限？

**理论局限性**:

1. **梯度方差 ≠ 重建误差**
   ```
   假设：梯度方差大 → 学习活跃 → 需要更多点
   问题：梯度方差大可能是：
         - 重建误差大 (期望情况)
         - 学习率过大 (非期望)
         - 噪声区域 (非期望)
         - 遮挡边界 (非期望)
   ```

2. **与 Hessian 方法的理论差距**
   
   | 方法 | 理论依据 | 准确性 | 计算成本 |
   |------|---------|--------|---------|
   | **Hessian 对角线** | 二阶优化 | 高 | 高 |
   | **梯度方差** | 一阶近似 | 中 | 低 |
   | **渲染误差** | 直接目标 | 高 | 中 |
   
   **结论**: 梯度方差是折中方案，理论上不如 Hessian 严谨

3. **缺乏严格的收敛性证明**
   - 标准 3DGS：grad > threshold (有启发式依据)
   - C1 方案：基于相对排序 (无绝对阈值)
   - 可能导致某些区域永远不被分裂
