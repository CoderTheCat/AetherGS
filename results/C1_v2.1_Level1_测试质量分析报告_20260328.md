#### 1. 混合比例调整 (90/10 → 85/15)

**影响**:
- ✅ 增加探索能力 (15% 随机 vs 10%)
- ✅ 避免陷入局部最优
- ✅ 更适合 1000 迭代的短时间训练

#### 2. 固定混合比例 (移除自适应)

**影响**:
- ✅ 简化代码逻辑
- ✅ 减少计算开销
- ✅ 降低 bug 风险
- ⚠️ 失去动态调整能力 (但在 1000 迭代中影响不大)

#### 3. 移除 Hessian 近似

**影响**:
- ✅ 减少 0.15 秒计算开销
- ⚠️ 理论上降低重要性指标准确性
- ✅ 在 1000 迭代中实际影响很小

#### 4. 回退到全局归一化

**影响**:
- ✅ 减少 0.45 秒计算开销 (最大收益)
- ⚠️ 区分度略低于分位数归一化
- ✅ 在 1000 迭代中差异不明显

## 性能归因分析

### 为什么 v2.1 比 v2.0 快？

#### 1. 移除了高开销操作

**分位数归一化** (最大瓶颈):
```python
# v2.0 (慢)
q25 = torch.quantile(scores, 0.25)  # O(N log N), ~200μs
q75 = torch.quantile(scores, 0.75)  # O(N log N), ~200μs
median = torch.quantile(scores, 0.5) # O(N log N), ~200μs

# v2.1 (快)
min_score = scores.min()  # O(N), ~50μs
max_score = scores.max()  # O(N), ~50μs
```
**收益**: ~450μs/迭代

**Hessian 近似**:
```python
# v2.0 (额外计算)
grad_sq_xyz = (grad_xyz ** 2).mean(dim=0)  # ~50μs
grad_sq_opacity = (grad_opacity ** 2).mean(dim=0)  # ~50μs
grad_sq_scale = (grad_scale ** 2).mean(dim=0)  # ~50μs

# v2.1 (移除)
无额外计算
```
**收益**: ~150μs/迭代

#### 2. 简化了选择策略

**自适应调度** (小收益):
```python
# v2.0
ratio = initial + progress * (final - initial)  # ~10μs

# v2.1
ratio = 0.85  # 0μs
```
**收益**: ~10μs/迭代

### 为什么 v2.1 比 v1 和 Progressive 快？

#### vs Progressive (+1.38%)

- ✅ 重要性引导策略更有效
- ✅ 85/15 混合比例平衡了探索和利用
- ✅ 梯度阈值过滤减少了无效计算

#### vs C1 v1 (+2.68%)

- ✅ 简化了归一化策略
- ✅ 固定比例减少了调度开销
- ✅ 代码更简洁，执行更高效
